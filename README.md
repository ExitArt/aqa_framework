### 🚀 Full-Stack Enterprise AQA Ecosystem [SauceDemo & Backend Services]
**Высокотехнологичный многоуровневый фреймворк автоматизации тестирования (UI + REST API + Асинхронные очереди Kafka + Интеграция с Базой Данных PostgreSQL + Виртуализация сервисов WireMock)**

Проект представляет собой готовую к продакшену экосистему автоматизации для e-commerce платформ. Фреймворк спроектирован с соблюдением лучших практик enterprise-разработки (SOLID, DRY, OOP), полностью потокобезопасен (Thread-Safe) и адаптирован для бесшовного запуска в изолированных Docker-контейнерах внутри CI/CD-пайплайна.

---

## 🛠️ Стек технологий и Инструменты
* **Core & Language:** Java 23 (с поддержкой новейших фич языка), ООП, паттерны проектирования.
* **Web Automation:** Playwright Java (высокоскоростной современный движок, изоляция Browser Context, Download API).
* **API Testing:** REST Assured (валидация HTTP-контрактов, маппинг в POJO-модели через Jackson).
* **Message Broker:** Apache Kafka (асинхронное тестирование событийной архитектуры в KRaft-режиме).
* **Database Layer:** PostgreSQL + JDBI3 Core (быстрые SQL-проверки состояния таблиц без утечек памяти).
* **Service Virtualization:** WireMock Server (изоляция бэкенда, динамическая конфигурация Stubs & Mocks в Docker).
* **Test Runner:** JUnit 5 (многопоточный параллельный запуск, параметризованные Data-Driven сценарии).
* **Data Generation:** Net Datafaker (генерация реалистичных локализованных данных на лету).
* **CI/CD & Security:** GitHub Actions (оркестрация параллельных Docker-сервисов) + Dependabot + GitHub Secrets.
* **Reporting:** Allure Report (детальные шаги, графики, автоматическое прикрепление PDF-артефактов).

## 🏗️ Структура и Архитектура проекта

Код жестко разделен на независимые логические слои (Decoupled Architecture) для обеспечения максимальной поддерживаемости:

```text
aqa_framework/
├── .github/workflows/
│   └── java-tests.yml        # CI/CD пайплайн (Сборка, параллельные сервисы, деплой Allure)
├── .github/
│   └── dependabot.yml        # Автоматическое отслеживание и обновление зависимостей
├── src/main/java/
│   ├── models/               # Data Transfer Objects (DTO) и POJO-классы для сериализации
│   │   ├── E2eOrderDto.java
│   │   ├── OrderDto.java
│   │   └── TestDataUser.java
│   ├── pages/                # Page Object Model (POM) — локаторы и UI-взаимодействие
│   │   ├── LoginPage.java
│   │   └── ProductsPage.java
│   ├── steps/                # Потокобезопасные шаги бизнес-логики для всех слоев
│   │   ├── ApiSteps.java
│   │   ├── AssertSteps.java
│   │   ├── DbSteps.java
│   │   ├── KafkaSteps.java
│   │   └── WireMockSteps.java
│   └── utils/                # Системные конфигураторы и инфраструктурные хелперы
│       ├── DbConfig.java     # Безопасный читалщик секретов из .env и окружения
│       ├── JsonReader.java   # Парсер тестовых дата-сетов через Jackson
│       ├── KafkaProducerUtils.java
│       └── KafkaUtils.java   # Менеджер консьюмеров очередей брокера
├── src/test/java/
│   └── tests/                # Изолированные тестовые сценарии (UI, API, E2E, DDT)
├── src/test/resources/       # Конфигурации тестовой среды и внешние данные
│   ├── junit-platform.properties  # Конфигурация параллельного движка JUnit 5
│   └── users.json            # Параметризованные наборы пользователей для DDT
├── wiremock/                 # Локальный том для хранения статических mappings WireMock
├── .env                      # Локальные зашифрованные секреты (скрыт от Git)
├── .gitignore                # Исключение служебных папок (.idea, target, .allure) и секретов
├── docker-compose.yml        # Локальная оркестрация инфраструктуры (Kafka, Postgres, WireMock)
└── pom.xml                   # Декларативное управление зависимостями Maven
```

## 📈 Покрытые сценарии (Тестовые Сьюты)

1. **Full-Stack E2E Workflow (Сквозной бизнес-процесс):**
   * Пользователь на UI (`ProductsPage`) оформляет заказ и скачивает реальный инвойс (Download API).
   * Фреймворк проверяет, что виртуальный бэкенд сохранил запись в таблицу **PostgreSQL** со статусом `CREATED` (проверка через JDBI).
   * Тест перехватывает и валидирует асинхронное JSON-событие в топике брокера **Apache Kafka** с помощью `KafkaUtils`.
2. **Data-Driven Testing (Тестирование на основе данных):**
   * Параметризованный тест считывает массив пользователей разного типа из внешнего файла `users.json` через `JsonReader`.
   * Автоматически запускает изолированные параллельные потоки, сбрасывая сессионные куки браузера между прогонами.
   * Успешно локализует заложенные дефекты окружения на специфических данных (тестирование под `problem_user`).
3. **Service Virtualization & Contract Testing (API + WireMock):**
   * Динамическое развёртывание правил заглушек (Stubs) во внешнем Docker-контейнере WireMock через `WireMockSteps`.
   * Имитация ответов бэкенда (`201 Created`) и валидация сетевых контрактов через REST Assured.
   * Mock-верификация поведения системы (проверка истории журналов вызовов `exactly(1)`).

## 🔐 Безопасность проекта (Enterprise Security)
Проект спроектирован с полным отсутствием хардкода конфиденциальных данных (Credential Leaks):
* **Локально:** Все секреты (пароли к базам данных) вынесены в скрытый файл `.env`, заблокированный в `.gitignore`. Пароли сайта передаются через системные свойства.
* **В облаке:** Секреты полностью изолированы и шифруются с помощью **GitHub Repository Secrets** [1.13].
* **Потокобезопасность:** Инициализация структуры базы данных и сброс таблиц (`TRUNCATE ... RESTART IDENTITY`) защищены ключевым словом `synchronized` от состояния гонки потоков (Race Conditions) [1.4]. Ввод пароля сайта закрыт проверкой на `IllegalStateException`.

## ⚙️ Локальный запуск инфраструктуры и тестов

### 1. Поднятие экосистемы в Docker
Перед запуском тестов необходимо развернуть инфраструктурные контейнеры (Kafka, PostgreSQL, WireMock). Убедитесь, что у вас установлен Docker Desktop, создайте локальный файл `.env` в корне проекта по шаблону и выполните в терминале:
```bash
docker compose up -d
```
*После этого вам станут доступны: порт СУБД `5432`, брокер `9092` и административный JSON-интерфейс WireMock `http://localhost:8080/__admin/mappings`.*

### 2. Запуск автотестов
**Вариант А (Через консоль):** Для запуска всего многопоточного тестового сьюта с принудительной передачей системного пароля, выполните:
```bash
mvn clean test -Dtest.password=secret_sauce
```

**Вариант Б (Через интерфейс IntelliJ IDEA):** Кликните правой кнопкой мыши по папке `src/test/java/tests/` -> **Run 'All Tests'** (предварительно добавив `-Dtest.password=secret_sauce` в глобальный шаблон JUnit в *VM options*).

## 📊 CI/CD Пайплайн и Отчетность

### Интеграция с GitHub Actions
Воркфлоу (`java-tests.yml`) полностью автоматизирован:
* Срабатывает по триггеру `push` в ветку `main`.
* Поднимает в облаке изолированные сервисы Kafka, WireMock и PostgreSQL с проверкой их здоровья (`pg_isready`) [1.14].
* Компилирует проект на Java 23, накатывает структуру таблиц на лету и параллельно прогоняет тесты [1.4, 1.10].
* Генерирует интерактивный Allure-отчет и деплоит его на **GitHub Pages**.
